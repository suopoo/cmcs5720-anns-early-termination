# 实验二：逐查询预测误差分析（中文摘要）

数据：GIST1M，992,000 条索引向量，k=100，目标 Recall 0.95；训练 2,000 /
验证 500 / 测试 1,000 条互不重叠的 Query。所有结果来自 `data/per_query.csv`
与 `analysis/*.csv`。

## 1. 三种方法的整体表现

| 方法 | 平均 Recall | 达标率 | 平均 NDC | 相对额外 NDC | Oracle 可达率 |
|---|---|---|---|---|---|
| LAET | 0.9562 | 0.676 | 12,150 | 0.799 | 0.980 |
| DARTH | 0.9608 | 0.644 | 12,691 | 1.063 | 0.926 |
| ANNiE-S | **0.9736** | **0.838** | 15,996 | 0.935 | 0.980 |

ANNiE-S 的达标率最高，但平均多花约 3,800 NDC；LAET 与 DARTH 的成本接近，
LAET 的达标率略高、相对额外 NDC 更低。

## 2. 失败 Query 是否重合

按 Query ID 取交集，并以 Oracle NDC 分层做置换检验（2,000 次）：

| 失败类型 | 交集 | Jaccard | P(B|A) | 分层置换 p |
|---|---|---|---|---|
| Quality: LAET∩DARTH | 225 | 0.495 | 0.694 | 0.0005 |
| Quality: LAET∩ANNiE | 122 | 0.335 | 0.377 | 0.0005 |
| Quality: DARTH∩ANNiE | 149 | 0.404 | 0.419 | 0.0005 |
| Efficiency: LAET∩DARTH | 17 | 0.147 | 0.250 | 0.0015 |
| Efficiency: LAET∩ANNiE | 46 | 0.434 | 0.676 | 0.0005 |
| Efficiency: DARTH∩ANNiE | 17 | 0.129 | 0.262 | 0.0005 |

**118 条 Query 三种方法同时质量失败。** 控制 Oracle 成本分层后，重合仍显著
高于随机预期，因此不能只用“Query 本身难”解释；三种方法存在共享的失败模式，
同时效率失败的重合较弱，说明浪费型失败更具方法特异性。

## 3. 训练规模、训练分布与目标 Recall

- 训练规模 500→2,000（3 个种子均值）：ANNiE 达标率 0.769→0.838，
  DARTH 0.633→0.653，LAET 0.651→0.676。
- Hard-query-enriched（1,000 条，D0 vs D2）：LAET 0.596→0.624，
  DARTH 0.654→0.724，ANNiE 0.848→0.908；但 NDC 分别从
  10,881→11,850、12,894→14,324、15,652→18,119 上升，收益不是免费的。
- 目标 Recall 0.90/0.95/0.99：LAET 0.604/0.676/0.687；
  DARTH 0.703/0.644/0.584（目标提高反而下降）；
  ANNiE 0.854/0.838/0.703。

## 4. 假设判定

- H1（误差分布不同）：支持。三种方法的误差单位与尾部不同，成本误差与
  Recall 误差分开报告。
- H2（失败 Query 非随机重合）：支持。质量失败交集显著；但控制 Query 难度后
  仍有剩余重合，说明“共享难度 + 方法缺陷”共同作用。
- H3（两类错误后果不对称）：支持。LAET/ANNiE 低估成本会造成预算不足；
  DARTH 高估 Recall 会造成假停止（per_checkpoint.csv 的 FP/FN 标记）。
- H4（训练规模/分布/目标影响误差）：部分支持。ANNiE 随规模单调改善，
  DARTH 基本平坦，LAET 非单调；Hard 富集提升达标率但增加 NDC；DARTH 对
  高目标更敏感（0.99 时达标率下降）。

## 5. 局限

Python 实现；992k 索引；实验二训练集为 2,000 条；DARTH 的 ef=2048 只能达到
平均 recall@100=0.9855（未到 0.99），因此其 Oracle 可达率 92.6%；无界束宽
轨迹在达到目标后停止，超出轨迹的预算会被标记为截断。
